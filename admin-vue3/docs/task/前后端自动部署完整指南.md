## 方案概述

### 架构说明

```
┌─────────────────────────────────────────────┐
│           GitHub Repository                  │
│  (推送代码到 main/master/deploy 分支)         │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│         GitHub Actions (CI/CD)               │
│  1. 检出代码                                 │
│  2. SSH 连接服务器                           │
│  3. 上传代码                                 │
│  4. 执行 docker-compose build & up          │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│         1Panel 服务器                        │
│                                              │
│  ┌─────────────┐    ┌──────────────┐        │
│  │   MySQL      │    │    Redis     │        │
│  └──────┬──────┘    └──────┬───────┘        │
│         │                  │                 │
│         ▼                  ▼                 │
│  ┌─────────────────────────────────┐        │
│  │      NestJS Backend (8080)      │        │
│  └──────────────┬──────────────────┘        │
│                 │                            │
│                 ▼                            │
│  ┌─────────────────────────────────┐        │
│  │   Nginx + Vue3 Frontend (80)    │        │
│  └─────────────────────────────────┘        │
└─────────────────────────────────────────────┘
```

### 工作流程

1. **本地开发** → 提交代码到 Git
2. **推送到 GitHub** → 触发指定分支（main/master/deploy）
3. **GitHub Actions 自动执行**：
   - 通过 SSH 连接服务器
   - 上传最新代码
   - 执行 `docker-compose build`
   - 执行 `docker-compose up -d`
4. **服务自动重启** → 访问网站验证

## 第一步：创建前端 Dockerfile

在 `admin-vue3/Dockerfile` 文件中添加以下内容：

```dockerfile
# 第一阶段：构建
FROM node:20-alpine AS builder

WORKDIR /app

# 安装 pnpm
RUN npm install -g pnpm@8

# 复制 package.json 和 pnpm-lock.yaml
COPY package.json pnpm-lock.yaml ./

# 安装依赖
RUN pnpm install --frozen-lockfile

# 复制源代码
COPY . .

# 构建项目（生产环境）
RUN pnpm build:prod

# 第二阶段：使用 Nginx 提供静态文件服务
FROM nginx:alpine

# 复制自定义 Nginx 配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

# 复制构建产物
COPY --from=builder /app/dist /usr/share/nginx/html

# 暴露 80 端口
EXPOSE 80

# 启动 Nginx
CMD ["nginx", "-g", "daemon off;"]
```

**说明：**
- 使用多阶段构建，减小最终镜像体积
- 第一阶段用 Node.js 构建 Vue3 项目
- 第二阶段用 Nginx 提供静态文件服务
- 使用 Alpine 基础镜像，体积小、速度快

## 第二步：创建前端 Nginx 配置

在 `admin-vue3/nginx.conf` 文件中添加以下内容：

```nginx
server {
    listen 80;
    server_name localhost;
    
    root /usr/share/nginx/html;
    index index.html;
    
    # 开启 gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
    gzip_min_length 1024;
    
    # 处理前端路由 - 所有请求都返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    # 静态资源缓存优化
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
    
    # API 请求代理到后端容器
    location /api/ {
        proxy_pass http://server:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
    
    # 图片资源代理
    location /uploads/ {
        proxy_pass http://server:8080/uploads/;
    }
    
    location /profile/ {
        proxy_pass http://server:8080/profile/;
    }
}
```

**关键点说明：**
- `try_files $uri $uri/ /index.html;` - 确保 Vue Router 的 History 模式正常工作
- `proxy_pass http://server:8080/;` - 将 API 请求代理到后端容器（Docker 网络中使用服务名）
- 静态资源设置 30 天缓存，提升加载速度

## 第四步：创建 GitHub Actions 工作流

### 4.1 创建工作流文件

在项目根目录创建 `.github/workflows/deploy.yml` 文件：

```yaml
name: Deploy Full Stack to Server

on:
  push:
    branches: [main, master, deploy]  # 推送到这些分支时触发
  workflow_dispatch:  # 允许手动触发

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
      # 1. 检出代码
      - name: Checkout code
        uses: actions/checkout@v3
      
      # 2. 设置 SSH 密钥
      - name: Setup SSH
        uses: webfactory/ssh-agent@v0.7.0
        with:
          ssh-private-key: ${{ secrets.SSH_PRIVATE_KEY }}
      
      # 3. 添加服务器到 known_hosts
      - name: Add server to known hosts
        run: |
          mkdir -p ~/.ssh
          ssh-keyscan -H ${{ secrets.SERVER_HOST }} >> ~/.ssh/known_hosts
      
      # 4. 上传代码到服务器
      - name: Upload code to server
        run: |
          rsync -avz --delete \
            -e "ssh -o StrictHostKeyChecking=no" \
            --exclude '.git' \
            --exclude 'node_modules' \
            --exclude 'dist' \
            --exclude '.env' \
            ./ \
            ${{ secrets.SERVER_USER }}@${{ secrets.SERVER_HOST }}:${{ secrets.DEPLOY_PATH }}/
      
      # 5. 在服务器上构建和部署
      - name: Build and Deploy on Server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          port: ${{ secrets.SERVER_PORT }}
          script: |
            cd ${{ secrets.DEPLOY_PATH }}
            
            echo "📦 开始部署..."
            
            # 创建或更新 .env 文件
            cat > .env << EOF
            MYSQL_ROOT_PASSWORD=${{ secrets.MYSQL_ROOT_PASSWORD }}
            MYSQL_DATABASE=${{ secrets.MYSQL_DATABASE }}
            MYSQL_HOST=mysql
            MYSQL_PORT=3306
            MYSQL_USERNAME=root
            REDIS_HOST=redis
            REDIS_PORT=6379
            REDIS_PASSWORD=
            SERVER_PORT=8080
            WEB_PORT=80
            EOF
            
            # 停止旧容器
            echo "🛑 停止旧容器..."
            docker-compose down || true
            
            # 构建新镜像
            echo "🔨 构建新镜像..."
            docker-compose build --no-cache
            
            # 启动新容器
            echo "🚀 启动新容器..."
            docker-compose up -d
            
            # 等待服务启动
            echo "⏳ 等待服务启动..."
            sleep 10
            
            # 检查容器状态
            echo "📊 容器状态："
            docker-compose ps
            
            # 查看日志（最后50行）
            echo "📝 最新日志："
            docker-compose logs --tail=50
            
            echo "✅ 部署完成！"
```

### 4.2 工作流说明

**触发条件：**
- 推送到 `main`、`master` 或 `deploy` 分支
- 或者在 GitHub Actions 页面手动触发

**执行步骤：**
1. 检出代码
2. 设置 SSH 密钥
3. 添加服务器指纹到 known_hosts
4. 使用 rsync 上传代码（排除不必要的文件）
5. 在服务器上执行部署脚本

## 第五步：配置 GitHub Secrets

### 5.1 进入 GitHub Secrets 配置页面

1. 打开你的 GitHub 仓库
2. 点击 **Settings** 标签
3. 左侧菜单找到 **Secrets and variables** → **Actions**
4. 点击 **New repository secret**

### 5.2 添加以下 Secrets

| Secret 名称 | 说明 | 示例值 |
|------------|------|--------|
| `SERVER_HOST` | 服务器 IP 地址 | `123.45.67.89` |
| `SERVER_USER` | 服务器用户名 | `root` |
| `SERVER_PORT` | SSH 端口号 | `22` |
| `SSH_PRIVATE_KEY` | SSH 私钥内容 | （见下方获取方法） |
| `DEPLOY_PATH` | 服务器部署路径 | `/opt/nest-admin` |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | `YourStrongPassword123` |
| `MYSQL_DATABASE` | 数据库名称 | `nest_admin` |

### 5.3 获取 SSH 私钥

#### 方法一：如果已有 SSH 密钥

```bash
# 查看私钥内容
cat ~/.ssh/id_rsa

# 复制全部内容（包括 BEGIN 和 END 行）
# 粘贴到 GitHub Secrets 的 SSH_PRIVATE_KEY 中
```

#### 方法二：如果没有 SSH 密钥，先生成

```bash
# 生成新的 SSH 密钥
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# 按回车使用默认路径
# 可以设置 passphrase（密码短语），也可以留空

# 复制公钥到服务器
ssh-copy-id -p 22 root@你的服务器IP

# 查看私钥
cat ~/.ssh/id_rsa
```

**⚠️ 注意事项：**
- 私钥内容要完整复制，包括 `-----BEGIN RSA PRIVATE KEY-----` 和 `-----END RSA PRIVATE KEY-----`
- 不要泄露私钥给任何人
- 建议使用专门的部署密钥，而不是个人密钥

### 9.2 备份数据

创建备份脚本 `backup.sh`：

```bash
#!/bin/bash

BACKUP_DIR="/opt/backups/nest-admin"
DATE=$(date +%Y%m%d_%H%M%S)

# 从 .env 读取密码
source /opt/nest-admin/.env

mkdir -p ${BACKUP_DIR}

echo "📦 开始备份..."

# 备份数据库
echo "备份数据库..."
docker exec nest-admin-mysql mysqldump -u root -p${MYSQL_ROOT_PASSWORD} ${MYSQL_DATABASE} > ${BACKUP_DIR}/db_${DATE}.sql

# 备份上传文件
echo "备份上传文件..."
tar -czf ${BACKUP_DIR}/uploads_${DATE}.tar.gz -C /opt/nest-admin upload/

# 删除7天前的备份
echo "清理旧备份..."
find ${BACKUP_DIR} -type f -mtime +7 -delete

echo "✅ 备份完成：${BACKUP_DIR}"
echo "📁 备份文件："
ls -lh ${BACKUP_DIR}
```

使用方法：

```bash
# 添加执行权限
chmod +x backup.sh

# 执行备份
./backup.sh

# 设置定时任务（每天凌晨2点备份）
crontab -e
# 添加以下行：
# 0 2 * * * /opt/nest-admin/backup.sh >> /var/log/backup.log 2>&1
```

### 9.3 健康检查

创建健康检查脚本 `health-check.sh`：

```bash
#!/bin/bash

WEBSITE_URL="http://localhost"
API_URL="http://localhost:8080/api/health"

echo "🏥 健康检查..."

# 检查前端
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" ${WEBSITE_URL})
if [ "$HTTP_CODE" -eq 200 ]; then
    echo "✅ 前端正常 (HTTP ${HTTP_CODE})"
else
    echo "❌ 前端异常 (HTTP ${HTTP_CODE})"
fi

# 检查后端
API_RESPONSE=$(curl -s ${API_URL})
if [ $? -eq 0 ]; then
    echo "✅ 后端正常: ${API_RESPONSE}"
else
    echo "❌ 后端异常"
fi

# 检查容器状态
echo ""
echo "📊 容器状态："
docker compose ps
```

## 常见问题

### ❌ 问题1：SSH 连接失败

**错误信息：**
```
Permission denied (publickey,password).
```

**解决方案：**

```bash
# 1. 测试 SSH 连接
ssh -i ~/.ssh/id_rsa root@你的服务器IP

# 2. 检查 SSH 密钥是否正确
cat ~/.ssh/id_rsa.pub

# 3. 重新配置 SSH 密钥
ssh-copy-id -p 22 root@你的服务器IP

# 4. 检查服务器 SSH 配置
# 在服务器上执行
cat /etc/ssh/sshd_config | grep PermitRootLogin
# 确保是 PermitRootLogin yes

# 5. 重启 SSH 服务
systemctl restart sshd
```

### ❌ 问题2：Docker 构建失败 - 内存不足

**错误信息：**
```
Killed
npm ERR! errno 137
```

**解决方案：**

```bash
# 1. 增加 swap 空间
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 2. 清理 Docker 缓存
docker system prune -a

# 3. 关闭其他占用内存的服务
# 在 1Panel 中停止不需要的应用

# 4. 限制构建时的内存使用
# 修改 docker-compose.yml，添加：
# services:
#   server:
#     deploy:
#       resources:
#         limits:
#           memory: 1G
```

### ❌ 问题3：数据库连接失败

**错误信息：**
```
Error: connect ECONNREFUSED 127.0.0.1:3306
```

**解决方案：**

```bash
# 1. 检查 MySQL 容器是否启动
docker compose ps mysql

# 2. 查看 MySQL 日志
docker compose logs mysql

# 3. 检查 .env 文件配置
cat /opt/nest-admin/.env

# 4. 确保使用正确的 host（应该是 mysql，不是 localhost）
# 在 docker-compose.yml 中，MYSQL_HOST 应该是 mysql

# 5. 重启 MySQL 容器
docker compose restart mysql

# 6. 等待 MySQL 完全启动后再启动后端
docker compose up -d mysql
sleep 30
docker compose up -d server
```

### ❌ 问题4：前端无法访问后端 API

**错误信息：**
```
Network Error
ERR_CONNECTION_REFUSED
```

**解决方案：**

```bash
# 1. 检查 Nginx 配置
docker exec nest-admin-vue3 cat /etc/nginx/conf.d/default.conf

# 2. 测试后端是否可访问（从前端容器内）
docker exec nest-admin-vue3 curl http://server:8080/api/health

# 3. 检查后端容器是否正常运行
docker compose ps server
docker compose logs server

# 4. 检查 Docker 网络
docker network ls
docker network inspect nest-admin_nest-admin-net

# 5. 重启所有服务
docker compose down
docker compose up -d

# 6. 检查防火墙
# 确保 8080 端口在 Docker 内部网络中可访问
```

### ❌ 问题5：GitHub Actions 执行失败

**错误信息：**
```
Host key verification failed.
```

**解决方案：**

检查工作流中是否有这一步：

```yaml
- name: Add server to known hosts
  run: |
    mkdir -p ~/.ssh
    ssh-keyscan -H ${{ secrets.SERVER_HOST }} >> ~/.ssh/known_hosts
```

**其他常见错误：**

- **Secret 配置错误**：检查 GitHub Secrets 是否正确配置
- **SSH 密钥格式错误**：确保私钥完整，包括 BEGIN 和 END 行
- **权限问题**：确保 SSH 密钥有正确的权限（600）

### ❌ 问题6：前端页面刷新后 404

**原因：** Nginx 没有配置 `try_files`

**解决方案：**

确保 `nginx.conf` 中有：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

然后重启前端容器：

```bash
docker compose restart admin-vue3
```

### ❌ 问题7：图片上传后无法访问

**原因：** 静态资源路径未配置代理

**解决方案：**

确保 `nginx.conf` 中有：

```nginx
location /uploads/ {
    proxy_pass http://server:8080/uploads/;
}

location /profile/ {
    proxy_pass http://server:8080/profile/;
}
```

### A. Docker Compose 完整配置参考

```yaml
version: '3.8'

services:
  mysql:
    image: mysql:8.0
    container_name: nest-admin-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
    ports:
      - "3306:3306"
    volumes:
      - ./mysql_data:/var/lib/mysql
      - ./server/db/init.sql:/docker-entrypoint-initdb.d/init.sql
    command: --default-authentication-plugin=mysql_native_password
    networks:
      - nest-admin-net
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:alpine
    container_name: nest-admin-redis
    ports:
      - "${REDIS_PORT}:6379"
    volumes:
      - ./redis_data:/data
    networks:
      - nest-admin-net

  server:
    build:
      context: ./server
      dockerfile: Dockerfile
    container_name: nest-admin-server
    environment:
      NODE_ENV: production
      MYSQL_HOST: ${MYSQL_HOST}
      MYSQL_PORT: ${MYSQL_PORT}
      MYSQL_USERNAME: ${MYSQL_USERNAME}
      MYSQL_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      REDIS_HOST: ${REDIS_HOST}
      REDIS_PORT: ${REDIS_PORT}
      REDIS_PASSWORD: ${REDIS_PASSWORD}
    ports:
      - "${SERVER_PORT}:8080"
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    networks:
      - nest-admin-net
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost:8080/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

  admin-vue3:
    build:
      context: ./admin-vue3
      dockerfile: Dockerfile
    container_name: nest-admin-vue3
    ports:
      - "80:80"
    depends_on:
      - server
    networks:
      - nest-admin-net
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost:80"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 10s

networks:
  nest-admin-net:
    driver: bridge
```
