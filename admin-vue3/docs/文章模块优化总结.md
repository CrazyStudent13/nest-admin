# 文章模块优化总结

## 🎯 优化目标

将文章模块的核心业务逻辑抽取为**语义化清晰、平台无关**的组合函数，以便：
1. ✅ 在当前的 Vue3 项目中更好地组织代码
2. ✅ **未来能够在 Nuxt 端直接复用**（核心目标）

## 📦 交付成果

### 1. 核心组合函数
**文件**: [`src/composables/useArticle.ts`](../src/composables/useArticle.ts)

提供 8 个语义化方法：
```typescript
const articleManager = useArticle()

// 数据查询
await articleManager.loadList(params)      // 加载列表
await articleManager.getDetail(id)         // 获取详情

// CRUD 操作
await articleManager.createArticle(data)   // 创建
await articleManager.updateArticle(data)   // 更新
await articleManager.deleteArticle(id)     // 删除

// 审核发布流程
await articleManager.submitForAudit(id)    // 提交审核
await articleManager.performAudit(params)  // 执行审核
await articleManager.publishArticle(id)    // 发布文章
```

### 2. 完整的类型定义

```typescript
interface Article              // 文章数据

```

## ✨ 核心优势

### 1. 语义化设计 🎨

| 传统命名 | 新命名 | 优势 |
|---------|--------|------|
| `listArticle()` | `loadList()` | "加载"更直观 |
| `getArticle()` | `getDetail()` | 明确表示"详情" |
| `addArticle()` | `createArticle()` | RESTful 风格 |
| `delArticle()` | `deleteArticle()` | 完整单词 |
| `submitAudit()` | `submitForAudit()` | 意图更清晰 |
| `auditArticle()` | `performAudit()` | 强调"执行"动作 |

**好处**：
- 🧠 降低认知负担，见名知意
- 👥 团队协作更高效
- 🔍 代码审查更轻松

### 2. 平台无关性 🌐

**设计原则**：
```typescript
// ❌ 避免 Vue 特定 API
import { ref, reactive } from 'vue'  // 不在组合函数内部使用

// ✅ 纯业务逻辑
export function useArticle() {
  return {
    loadList: async (params) => { ... },
    createArticle: async (data) => { ... }
  }
}
```

**结果**：
- ✅ 可在 Vue3 项目中使用
- ✅ 可在 Nuxt 3 项目中使用
- ✅ 可在任何支持 TypeScript 的环境中使用

### 3. 类型安全 🔒

```typescript
// 自动类型提示和检查
const article = await articleManager.getDetail(123)
// article 类型为 Article，IDE 会提示所有属性

await articleManager.updateArticle({
  id: 123,
  title: '新标题',
  // invalidProp: 'xxx'  // ❌ TypeScript 会报错
})
```

**好处**：
- 🛡️ 编译时错误检测
- 💡 IDE 智能提示
- 📝 自文档化代码

### 4. 统一错误处理 ⚠️

```typescript
// 所有方法都有统一的错误日志
try {
  await articleManager.createArticle(data)
} catch (error) {
  // 控制台会自动输出：
  // "创建文章失败: [错误详情]"
}
```

**好处**：
- 🐛 更容易调试
- 📊 统一的错误追踪
- 🔧 便于添加全局错误处理

## 🚀 Nuxt 复用方案

### 步骤 1: 复制文件

```bash
# 从 admin-vue3 复制到 nuxt-project
cp src/composables/useArticle.ts ../nuxt-project/composables/
cp src/types/api.d.ts ../nuxt-project/types/
```

### 步骤 2: 调整导入路径

```typescript
// Nuxt 项目中
import { useArticle } from '~/composables/useArticle'
import type { Article } from '~/types/api'
```

### 步骤 3: 在 Nuxt 中使用

```vue
<!-- pages/articles/index.vue -->
<script setup lang="ts">
const articleManager = useArticle()

// SSR 数据获取
const { data } = await useAsyncData('articles', () => 
  articleManager.loadList({ pageNum: 1, pageSize: 10 })
)

// 客户端操作
const deleteArticle = async (id: number) => {
  await articleManager.deleteArticle(id)
  await refreshNuxtData('articles')
}
</script>
```

**零修改！** 组合函数可以直接运行。

## 📈 对比改进

### 改进前

```javascript
// 分散在各处的 API 调用
import { listArticle, delArticle } from '@/api/post/article'

const getList = () => {
  listArticle(query).then(res => {
    list.value = res.data.list
  }).catch(err => {
    console.error(err)
  })
}

const handleDelete = (row) => {
  delArticle(row.id).then(() => {
    getList()
  })
}
```

**问题**：
- ❌ 代码重复
- ❌ 错误处理不统一
- ❌ 缺乏类型安全
- ❌ 难以复用

### 改进后

```typescript
// 统一的组合函数
import { useArticle } from '@/composables/useArticle'

const articleManager = useArticle()

const loadArticles = async () => {
  const { list } = await articleManager.loadList(query)
  articles.value = list
}

const deleteArticle = async (id: number) => {
  await articleManager.deleteArticle(id)
  await loadArticles()
}
```

**优势**：
- ✅ DRY 原则（Don't Repeat Yourself）
- ✅ 统一错误处理
- ✅ 完整类型支持
- ✅ 跨平台复用

1. **语义化** → 代码即文档，降低理解成本

4. **易于维护** → 逻辑集中，修改一处，处处生效

- 从"功能实现"到"用户体验"（开发者体验）
- 从"单次使用"到"可复用性"
