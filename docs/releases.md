# 发布记录

这里按版本记录部署内容、升级注意事项和对应的 Git 标签。新版本发布时，在「版本一览」、侧边栏时间线和「版本详情」顶部各追加一条，最新的放最上面。

## 版本详情

### v1.0.1

**发布日期**：2026-10-25　**Git 标签**：`v1.0.1`

文档站接入开发环境，部署流水线改为由 `master` 触发。

#### 新增

- 文档站支持中英文标题切换，只切换导航、侧边栏和页面标题，正文保持中文
- 新增「发布记录」页，侧边栏以时间线形式展示历史版本
- 开发环境通过前端 8888 的 `/manual/` 访问文档，首页新增「项目文档」入口
- `bin/dev.sh` 同时启动文档服务，并在启动前释放 5173 端口

#### 变更

- 部署工作流触发分支由 `feature-1.0` 改为 `master`

#### 修复

- 文档服务就绪探测改用 `localhost`，避免 VitePress 仅监听 IPv6 时误报未就绪

#### 升级注意

- 「项目文档」入口仅在开发环境显示；生产环境需先发布文档产物并在 nginx 配置 `/manual` 路由

### v1.0.0

**发布日期**：2026-10-25　**Git 标签**：`v1.0.0`

首个部署版本，master 与 dev 对齐。

#### 新增

- 数据字典改为前端本地持久化缓存，并通过服务端版本号校验缓存是否过期，减少重复请求
- 新增本地一键启动脚本 `bin/dev.sh`，配套端口释放脚本 `scripts/free-port.mjs`
- 补充部署基建：GitHub Actions 与 `.workflow` 分支流水线
- 补充在线部署、自动部署与协作开发文档

#### 变更

- 后端字典缓存合并为单 key（`sys_dict:all`），减少 Redis key 数量
- 合并字典相关 composable，精简 store 结构
- 统一以 `feature-1.0` 作为上游唯一主线

#### 修复

- 修复字典查询中 LIKE 通配符未转义导致的注入风险
- 验证码改为按字符串比较，修复登录总是失败的问题
- 后端增加断线自愈，避免瞬时连接错误导致进程退出
- 修复静态图片路径被错误拼接 API 前缀
- 修复 404 页面 HTML 标签未闭合
- 为 Redoc 补充 CSP 指令并关闭 telemetry

#### 升级注意

- 字典缓存 key 变为 `sys_dict:all`，升级后建议清空旧的 `sys_dict:*` 缓存
- 前端缓存带 schema 版本号；字典结构有调整时，需要同步递增 `CACHE_SCHEMA_VERSION` 以触发刷新
- 仓库不再跟踪密钥与本地产物，部署时需自行提供 `.env` 等配置

## 新增一条发布记录

1. 确认 `master` 已合并完成，打标签并推送：

   ```bash
   git tag -a v1.1.0 -m "v1.1.0: <一句话概括>"
   git push origin v1.1.0
   ```

2. 在「版本一览」表格顶部新增一行。
3. 在 `.vitepress/config.mts` 的 `/releases` 侧边栏 `items` 顶部新增一条时间线记录：

   ```ts
   { text: 'v1.1.0 · YYYY-MM-DD', link: '/releases#v1-1-0' },
   ```

   锚点由版本号生成，`.` 会变成 `-`，例如 `v1.1.0` 对应 `#v1-1-0`。

4. 复制下面的模板，放到「版本详情」的最上方并填写内容，没有的小节可以删除。

```md
### v1.1.0

**发布日期**：YYYY-MM-DD　**Git 标签**：`v1.1.0`

#### 新增

-

#### 变更

-

#### 修复

-

#### 升级注意

-
```
